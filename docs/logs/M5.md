## 改动点

1. **Pipeline 主体**（`pipeline/`，设计 §6 漏斗 + Enhanced plan M5 骨架）：
   - `context.py` — `DetectionContext`（`@dataclass(kw_only=True)`，骨架 P0#7 修正）：`trace_id`/`tenant_id`/`domain`/`domain_config`（用 M1 冻结 `DomainConfig` typed 字段）/`registry`/`storage`/`state_store`/`sequence_store`/`now`/`targets`/`signals`/`changes`/`suppressed`/`anomalies`/`maintenance_windows`/`blacklist`/`fpr`/`degraded_sources`/`seen_keys`；`DomainResult`；`build_context` 从 `DomainConfigLoader` 载入 domain_config + 从 `storage.dynamic_config` 载入四类动态配置（changes 转 `ChangeSignal`），注入 state/sequence store。
   - `l0_suppress.py` — 遍历 `domain_config.suppressors`，`registry.get("suppressor", name)` → `batch_check(signals, ctx, params)`，产出 suppressed 审计 `[{signal, reason, suppressor}]` 并从 `ctx.signals` 移除。
   - `l1_detect.py` — 遍历 `domain_config.detectors`，`filter_signals(matched)` → `detector.detect(matched, params)`；**单 detector 异常隔离**（`try/except` 记 `logger.warning` 不拖垮整轮，M4 遗留 HIGH 落地）；`a.severity = dc.severity`（spec 权威覆盖，骨架 P1#12）；`MetricAnomaly.method = detector.name`（isinstance 守卫，`LogAnomaly` 无 method 字段）。
   - `l2_correlate.py` — 按 service 分组返回 `{service: (Correlation, change_related, recent_change)}`（骨架 2 元组，加 `recent_change` 满足 UC-5.5）；`_within_window`（指标+日志同源）、`_change_within_window`（部署变更关联）、`template_summary`（模板兜底摘要，零 LLM 调用）。reason：`metric_log_within_window`/`metric_only`/`log_only`/`unrelated`。
   - `l3_verify.py` — 持续性（per-key `fingerprint.anomaly_key`，**increment-first**：`new_consecutive = prev + 1` 再判 `>= persistence_rounds`，见下）+ 误报率闸门（`fpr_ok = total < min_samples or fpr < threshold`，**命中只降级 severity 不丢弃**，骨架 P0#8）+ `calibrate_severity`（取最高，组合升 critical 留 M6）。未通过返回 `Verification(passed=False, ...)`。
   - `emit.py` — `verification.passed` 才组装 `ProblemRecord`（record_id 从 sequence_store 取号、symptom 用 `template_summary`、degraded 标记写 evidence），`await storage.write_or_append(tenant_id, rec)` 原子去重（M2 实现返回 None，故直接返回 `[rec]`）。
   - `runner.py` — `run_domain(ctx)` 串行编排：`collect_done → L0 → L1 → L2 → 按 service L3+emit → state_store.sweep(seen_keys) → record_created`，返回 `DomainResult`。
2. **存储层**（`storage/`，ABC + InMemory + MySQL 三件套，各方法入口校验 `tenant_id` 非空）：
   - `sequence.py` — `SequenceStore.next_id(domain) -> PR-YYYYMMDD-NNNN`（`%04d` 当日自增）。InMemory 注入 `now` 可测跨日期；MySQL 用 `INSERT ... ON DUPLICATE KEY UPDATE next_seq = LAST_INSERT_ID(next_seq + 1)` + 同 handle `SELECT LAST_INSERT_ID()` 原子取号（LAST_INSERT_ID 连接作用域 → 单 handle 内完成）。
   - `detection_state.py` — `DetectionStateStore.get/upsert/sweep`：`{consecutive_rounds, miss_rounds, first_seen, last_seen}`；`sweep(tenant, domain, seen_keys)` 对本轮**未到到**（∉ seen_keys）的 key 记 `miss_rounds+1, consecutive_rounds=0`（UC-5.6 关键）。MySQL 存 `state_value` JSON，datetime 先 `.isoformat()`（`_as_json` 不能序列化 datetime）。
   - `dynamic_config.py` — `DynamicConfigStore.load_maintenance_windows/load_blacklist/load_fpr/load_changes`（设计 §9）：blacklist 只取 `enabled=1`、fpr DECIMAL→float、total_cnt→int。
   - `__init__.py` — `Storage` 加 `sequence`/`detection_state`/`dynamic_config`；`build_storage` memory→InMemory 三件套、mysql→MySQL 三件套。
3. **`pipeline/__init__.py`** — 导出 `DetectionContext`/`DomainResult`/`build_context`/`new_trace_id`/`filter_signals`/`l0_suppress`/`l1_detect`/`l2_correlate`/`l3_verify`/`emit`/`run_domain`。

## 关键实现决策（偏离 plan 骨架，均为正确性修正）

- **l3_verify increment-first**（plan 骨架先查 `consecutive >= persistence_rounds` 再 upsert，实现改为先 `new_consecutive = prev + 1` 再判）：语义「连续 N 轮出现 → 第 N 轮开单」。必须：UC-5.1（persistence_rounds=2）第二轮开单；单轮场景（persistence_rounds=1）第一轮开单。若按骨架先查后增，单轮场景永不通过（per-key state 首轮 consecutive=0）。
- **emit 直接返回 `[rec]`**：M2 `write_or_append` 已原子去重且返回 `None`（骨架 `actual_id == record_id` 比判不适用）；去重语义由 store 保证（UC-5.4「只有 1 条 record」）。
- **l2_correlate 返回 3 元组**：`(Correlation, change_related, recent_change)`（骨架 2 元组），`recent_change` 满足 UC-5.5 断言。
- **l1_detect `a.method` 用 isinstance 守卫**：`MetricAnomaly` 有 `method` 字段、`LogAnomaly` 无；`a.severity = dc.severity` 对两者都适用。
