## 改动点

1. **迁移层**（新增 `migrations/`）：
   - `runner.py` — `MigrationRunner`（`_load_scripts` / `_split_statements` / 幂等 `migrate`，钉住单连接执行建库+USE+脚本）；`run_migrations(settings)` 用 `db=None` 裸库连接；`main()` 为 `make migrate` 入口
   - `V1__init_tables.sql` — 12 张表一次建齐（problem_record 含 P0 列 severity/生命周期列 + `open_group_key` STORED 生成列 + `uk_open_group_key` UNIQUE 原子去重；change_record / domain_config / monitor_target / maintenance_window / suppress_blacklist / fpr_table / record_seq / scheduler_lease / signal_snapshot / detection_state / detection_round）
2. **存储层**（新增 `storage/`）：
   - `connection.py` — `ConnectionPool`（aiomysql：init/acquire/release/execute/fetchone/fetchall/health_check/close；`db=None` 迁移用、短超时 3s）
   - `records.py` — `RecordStore` ABC + `InMemoryRecordStore`（单测真源）+ `MySQLRecordStore`（生成列 + `INSERT ... ON DUPLICATE KEY UPDATE`，evidence 用 `JSON_MERGE_PRESERVE` 拼接、severity 用 `FIELD()` 取高）
   - `domain_config.py` — `DomainConfigStore` ABC + InMemory + MySQL（load/upsert/seed 幂等）
   - `__init__.py` — `Storage` 聚合 + `build_storage(settings)` 按 `storage_backend` 分派
3. **配置层**（新增 `config/`）：
   - `loader.py` — `DomainConfigLoader`（DB 主源 → 空表 seed → last-known-good 缓存回退，`reload` 清缓存）
   - `domains.yaml` — `application` 域 seed（3 detectors + 2 suppressors + correlation + verify）
4. **接入 app**：
   - `_app.py` lifespan：**fail-fast** 接线（`app.state.storage = await build_storage(settings)` 直接赋值，mysql backend 连不上 DB 抛异常 → uvicorn 启动失败退出；memory backend 无此约束）+ shutdown `storage.close()`
   - `router/api.py` `/ready`：`db = await storage.health_check() if storage else False`（memory 恒可用 / mysql 探活 / 构建失败 False）
   - `Makefile` `migrate` target：source `.env` + `python -m aiops_apm.migrations.runner`
   - `pyproject.toml`：+`pyyaml>=6.0`
   - `tests/conftest.py`：app fixture 用 `Settings(_env_file=None, storage_backend="memory")` 让 lifespan 跑真 storage
5. **测试**（TDD 六用例 UC-2.1~2.6 + 扩展，20 新增用例）：`tests/test_migrations.py`（5）、`tests/test_records.py`（7）、`tests/test_domain_config.py`（6）、`tests/test_storage.py`（2）；更新 `tests/test_health.py`（memory backend `/ready` reason 含 `'db': True`）

## 验证

1. `make lint` — ruff + mypy 通过（22 个源文件，含新 migrations/storage/config）
2. `make test` — 45 用例全过（原 25 不回归，新增 20）
3. 手动验证：
   - memory backend `make dev`：`/health` 200；`/ready` → 503 `{'db': True, 'plugins': False}`（db 就绪、插件 M4 再补）
   - mysql backend 连不上 DB：**fail-fast** 启动失败退出（`ERROR: Application startup failed. Exiting.`，用户确认由降级改为 fail-fast）；运行中 DB 掉线则 `/ready` → 503 `{'db': False, 'plugins': False}`（lifespan 内 `build_storage` 已成功，此处反映运行时真实连接）
   - `make migrate` 连真 MySQL（`.env` 配 `APM_DB_*` 凭据后）：成功建齐 `aiops_apm_runtime` 12 张表 + `schema_versions`（`SHOW TABLES` 13 张）；二次执行幂等（`applied 0 script(s)`）。期间修复 `V1__init_tables.sql` 一个 bug：`suppress_blacklist.signal` 列名是 MySQL 8.0 保留字 `SIGNAL`，首次迁移报 `1064 SQL syntax error`，已加反引号 `` `signal` ``
