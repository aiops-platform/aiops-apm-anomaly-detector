## 改动点

1. **Prometheus 指标（UC-7.1）**：
   - `metrics.py` — 7 类指标模块级定义（`prometheus_client` 全局注册表）：`ROUND_TOTAL`（按 domain/tenant/status）、`ROUND_SUCCESS`、`RECORDS_CREATED`（按 service/severity）、`DEGRADED_SOURCES`、`SUPPRESSED_TOTAL`（按 service/suppressor，从 timeline suppressed details 摊平）、`FALSE_POSITIVE_RATE` Gauge（按 service，fpr_table 求均值）、`ROUND_DURATION` Histogram（自定义桶）。
   - `record_round_metrics(domain, tenant_id, status, duration_sec, result=None)` — 收尾打点；`update_fpr_gauge(tenant, domain, service, fpr_data)` — 按 group_key 前缀 `{tenant}:{domain}:{service}:` 求均值写 Gauge。
   - `_app.py` — `/metrics` 端点（`include_in_schema=False`）→ `generate_latest()`。
   - **caveat（docstring 已标注）**：`records_created` 按 `len(result.records)` 计数，忽略 `write_or_append` 去重 → 高估上限值，仅趋势观察。
2. **轮次审计（UC-7.2）**：
   - `storage/rounds.py` — `RoundStore` ABC + `InMemoryRoundStore`（真源）+ `MySQLRoundStore`（JSON 列 `_as_json`/`_decode_json`，单 handle）。`create_round`（running）→ `update_status`（success/partial/failed，收尾计数）→ `get_round`/`list_rounds`（domain/status 过滤 + started_at 倒序 + limit/offset）。每方法入口校验 `tenant_id` 非空。
   - `migrations/V3__detection_round_domain.sql` — `detection_round` 补 `domain` 列（V1 建表时未含，UC-7.2 审计按 domain 过滤需要）。
   - `poller.py` — 每轮 `rounds.create_round(round_id=trace_id, target_ids, started_at=now)` → `run_domain` → `update_status(success/partial/failed, timeline, 计数)`；`run_domain` 异常 → `failed` + 审计 + re-raise（保留调用方语义）；收尾 `record_round_metrics` 打点。
   - `pipeline/runner.py` — suppressed timeline 步骤加 `details`（signal/service/suppressor/reason，reason 截断 200 字符，JSON 安全字符串摘要）。
   - `router/audit.py` — `GET /v1/audit/rounds`（domain/status/limit 过滤）+ `GET /v1/audit/suppressed`（从 `list_rounds(limit=round_retention_rounds)` 的 timeline suppressed details 摊平，service 过滤）；普通鉴权（非 admin），`get_tenant_id` 租户隔离。
   - `router/api.py` — include audit router。
3. **detector params 写入侧校验（UC-7.3，M6 遗留项落地）**：
   - `config/validator.py` — `ConfigValidationError(AppException)`（错误码 `CONFIG_ERROR`）+ `validate_domain_config(cfg, registry)` 表驱动 schema：detector 的 static_threshold（`threshold` 必须数值）/simple_compare（`baseline` 或 `ratio` 至少一个，ratio 为正）/signature_aggregate（min_count/n_frames 正整数）+ suppressor 的 maintenance_window（duration_minutes 正）/blacklist（pattern 非空）；插件名不存在 → `ConfigValidationError`；registry 可解析但无内置 schema 的插件跳过结构校验。
   - `_app.py` `_status_for_code` — `ErrorCode.CONFIG_ERROR → 400`（此前走 500 兜底）。
   - `router/config.py` — `PUT /v1/config/{domain}` 在 `model_validate` 后接 `validate_domain_config(cfg, reg)`。
4. **安全审计日志（UC-7.6）**：
   - `audit.py` — `SecurityAudit` 五静态方法（auth/gateway/plugin/config/round）走 `logging.getLogger("aiops_apm.audit")` 结构化 key=value；`set_audit_enabled` 全局开关（`APM_AUDIT_ENABLED`，`_app` lifespan 注入）；**不记明文凭据**——API key 只留 sha256 前缀、URI 只留 host:port（去 query/secret）。
   - 接线：`auth/middleware.py` 401/403 分支 `log_auth_event(deny, detail="missing_or_invalid_key"/"tenant_out_of_scope")`、放行 `allow`；`collectors/_gateway.py` 各拒绝分支 `log_gateway_event`；`plugins/registry.py` load 成功/失败 `log_plugin_event`；`router/config.py` reload/put `log_config_event`；`poller.py` failed/partial 轮次 `log_round_event`。
5. **SSRF DNS 二次校验（UC-7.6，M3 docstring 遗留落地）**：
   - `collectors/_gateway.py` — 模块级 `_resolve_ips(host)`（`socket.getaddrinfo` 解析 A/AAAA 去重）；`validate_url` hostname 分支：解析后任一 IP 命中 `BLOCKED_NETWORKS`（含 `::1`）→ 拒绝；`socket.gaierror` → 拒绝（**fail-closed**，防 DNS rebinding 首查放行）。IP 字面量分支在 DNS 前执行（不回归）。`validate_url`/`validate_headers` 加可选 `trace_id` kwarg（契约只加不改）。
6. **fpr 回写（UC-7.6，M6 遗留项落地）**：
   - `storage/dynamic_config.py` — `write_fpr(tenant, group_key, *, false_positive)`：InMemory 递增 total + 重算 fpr；MySQL 单语句原子 `INSERT ... ON DUPLICATE KEY UPDATE total_cnt=total_cnt+1, false_positive_cnt=... , fpr=...`。
   - `router/problems.py` — `POST /v1/problems/{id}/resolve` 加可选 body `{"false_positive": true|false}`（默认 false）：有 group_key 时 `write_fpr` + `update_fpr_gauge` 重算 Gauge → 再 `resolve(reason="manual")`。返回 `false_positive_recorded`。
   - **record dict 自带 `group_key`/`service`/`domain`**，无需 reconcile 重建（plan 里抽公共函数的方案已简化）。

## 关键实现决策（偏离 plan 骨架，均为正确性修正）

- **V3 迁移**：plan 假设 V1 `detection_round` 已有 domain 列；实际 V1 DDL 未含 → 新增 `V3__detection_round_domain.sql`（ALTER TABLE ADD COLUMN domain DEFAULT 'application'）。
- **fail-closed DNS 二次校验破坏面**：hostname URL（如 `https://prometheus.example.com:9090`）过 `validate_url` 会真实 DNS 解析（本机可能失败 → fail-closed 拒绝）→ `test_collectors`/`test_monitors_api` 加 autouse `_resolve_ips` 公网 IP patch；`test_gateway` 单测试 patch。IP 字面量分支在 DNS 前执行，不受影响。
- **FastAPI 单 Body 标量陷阱**：`resolve` 的 `false_positive: bool = Body(False)` 会把整个请求体当作该标量 → 422。改 `body: dict | None = None` 可选 dict，读 `body.get("false_positive", False)`，兼容 `{}` 与空 body。
- **fpr 回写不重建 group_key**：plan 提议从 reconcile 抽公共重建函数；实现发现 `RecordStore.get` 返回的 record dict 已含 `group_key`/`service`/`domain`，直接用即可（M2 STORED 生成列产物），简化掉重建逻辑。
- **`records_created` 高估 caveat**：按 `len(result.records)` 计数忽略 `write_or_append` 去重，docstring 标注仅趋势观察。
- **runner suppressed details 上限**：reason 截断 200 字符、timeline 整体 `_json_safe`（datetime → isoformat），保证 JSON 列可序列化（`test_rounds::test_timeline_datetimes_serialized`）。
- **迁移脚本定位**：`MigrationRunner` 用 `Path(__file__).parent` 定位 SQL，wheel 安装后在 site-packages → Dockerfile 无需 COPY migrations。
