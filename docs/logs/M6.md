## 改动点

1. **调度 / 编排 / 恢复闭环**：
   - `scheduler.py` — `Scheduler`（UC-6.1/6.9）：`tick()` 单步可测（注入 `now_fn`/`jitter_fn`/`run_round_fn`，不真实 sleep）。每 tick 先抢 `scheduler` lease（抢不到返回 0，多副本单调度器）；`_next_run[(tenant, target_id)]` 首次观测初始化为 `now + interval`（避免启动即全量风暴），到点（`<= now`）触发，触发后重排为 `now + interval + jitter`；按 `(tenant, domain)` 分组、组内 in-flight 去重、`max_concurrent_rounds` 信号量（**惰性创建**，避免 pytest-asyncio 事件循环绑定）；`run()`/`stop()` 后台循环（`asyncio.wait_for(self._stop.wait(), timeout=...)`，py310 typeshed 无 `Event.wait(timeout=)`）。
   - `poller.py` — `run_round(*, registry, storage, tenant_id, domain, targets, now, ...)`：每个 target 用窄 `CollectContext(tenant_id, watermark_store, snapshot_store)`（collector duck-type 只用这三个字段，M3 冻结）走 `collector_for` 采集；`asyncio.gather` 并行；**单 target 异常 → 记入 `degraded_sources` 返回 [] 不崩溃**（M5 遗留「degraded_sources 产生」落地）；合并 signals → `build_context` → `run_domain`。
   - `reconcile.py` — `Reconciler`（UC-6.7）：`reconcile_once()` 遍历 `records.list_tenants()` → `records.list` 过滤 open states → 从 record JSON 重建 anomaly_keys（`MetricAnomaly`/`LogAnomaly` `.model_validate` + `fingerprint.anomaly_key`）→ `detection_state.list_by_domain` 取各 key `miss_rounds` → 全部 `>= resolve_after_rounds` 则 `records.resolve(reason="auto")`。
   - `storage/lease.py` — `LeaseStore` ABC + InMemory + MySQL（UC-6.9）：`try_acquire`/`renew`/`release`。InMemory 注入 `now` 可测过期接管；MySQL 用 `INSERT ... ON DUPLICATE KEY UPDATE holder = IF(expires_at < NOW(3), VALUES(holder), holder)` + `execute_affected()` 原子接管（单 handle）。
2. **多租户鉴权**（UC-6.8）：
   - `auth/__init__.py` — `Principal(api_key, tenants, is_admin)` + `get_principal(request)`（无中间件 → 匿名 admin，dev 兼容）+ `require_admin(principal)`。
   - `auth/middleware.py` — `AuthMiddleware`：解析 `Bearer <key>` → 查 `settings.api_keys`（无 → 401）→ scope 解析（`"*"` 或列表）→ `X-Tenant-Id` 超限 → 403；`is_admin = ("*" in tenants)`（master key 隐式 admin）。**配置了才强制**：`create_app` 中 `if settings.api_keys: add_middleware(...)`，未配置 = 放行（既有 API 测试零改动）。
3. **§13 用例 2（组合升 critical）**：`l3_verify.calibrate_severity(anomalies, *, related=False)` — related 且同 service 有 high metric + high log → `critical`；`l3_verify(..., related=corr.related)` 透传；`runner.py` 传 `corr.related`（M5 只取最高，M6 补组合）。
4. **LLM L2 摘要钩子**：`summary.py` — `SummaryProvider` Protocol + `TemplateSummaryProvider`（复用 `template_summary` 确定性模板）+ `build_summary_provider`（`enable_llm_summary` 开关，M6 不接真实 LLM）；`emit.py` 用 `ctx.summary_provider or TemplateSummaryProvider()`。

## 关键实现决策（偏离 plan 骨架，均为正确性修正）

- **`_due_targets` 首观测不 `continue`**：plan 骨架首观测初始化 `next_run = now + interval` 后 `continue`，导致 `interval=0`（测试用「立即到点」）永不触发。实现改为初始化后**落穿到到点判断**：`interval=0 → now+0 <= now` 首 tick 即 due；`interval=60 → 首 tick 不 due`（启动防风暴）。测试 `test_tick_groups_targets_by_tenant_domain` 断言 `tick() == 2` 暴露此 bug。
- **poller 采集用窄 `CollectContext`**（非完整 `DetectionContext`）：collector duck-type 只用 `tenant_id`/`watermark_store`/`snapshot_store`（M3 冻结），避免提前构造完整 ctx。
- **asyncio.Semaphore 惰性创建**：`__init__` 里构造会绑定事件循环，pytest-asyncio 每用例新 loop → 在 `_sem()` 首次调用时创建。
- **reconcile 租户发现用 `RecordStore.list_tenants()`**（与 MonitorTargetStore 对称）：reconcile 自包含，不依赖 monitor_target 是否存在。
- **`asyncio.Event.wait(timeout=)` 不可用**（py310 typeshed）：`run()` 循环用 `asyncio.wait_for(self._stop.wait(), timeout=...)` + 捕获 `asyncio.TimeoutError`。
- **mypy 类作用域 `list` 方法遮蔽**（M3 已知）：`RecordStore.list`/`list_tenants` 返回注解 `list[dict]` 被解析为方法 → `builtins.list[...]` 显式指代。
